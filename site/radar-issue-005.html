Access Foundation: Accounts, Verification and Utility

Issue 005 connected the Go China Access narrative to a practical account model: email registration, read-only Base wallet verification, holder utility records, and a clearly defined member path.

The design keeps user assets in the user’s wallet and separates account access from token transfers, trading permission, and custody.

Access Foundation

Theme Public account foundation

Registration, account access, read-only wallet verification, and holder utility records form one coherent user journey.

Theme Utility without custody

Credits, member records, and service requests are account-level workflow records. They are not cash, exchange custody, trading permission, or automatic token claims.

Theme Verifiable token identity

The Base Mainnet chain, GCA contract, quote asset, and official pool remain explicit throughout the access journey.

Operating Boundaries

  • Wallet verification uses a read-only ERC-20 balance call and does not require a wallet signature.
  • Credits and member records are account-level utility records, not transferable tokens or trading permission.
  • Member eligibility does not trigger an automatic token transfer.
  • Source verification does not replace an independent third-party audit.
  • Market depth, price impact, and slippage must be checked in the current pool before use.
