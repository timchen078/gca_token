GCA Member Access GCA 会员账户入口

This controlled HTTPS account UI submits a GCA member account request, verifies a Base wallet with read-only ERC-20 balanceOf, writes eligible 100-credit records, and queues GCA Member evidence for manual review.

中文用户可以在这里提交邮箱、Base 钱包地址、持有开始日期和公开交易哈希。后台只读取当前 GCA 余额；持有日期和交易哈希只作为人工审核材料，不会自动激活会员，也不会要求私钥、助记词、授权转账或钱包签名。

The 10,000 GCA member benefit is not automatic. If a member ledger becomes active, the benefit remains pending manual reserve-wallet transfer review.

10,000 GCA 会员权益不是自动领取。通过 GCA Member 记录后，仍需要支持团队人工审核和储备钱包处理。

After account creation, this browser can use a high-entropy device key to refresh redacted account, credits, member-review, and benefit-transfer status. The API stores only the key hash and never returns email or the key.

账户创建后，本浏览器可使用高强度设备密钥刷新脱敏的账户、积分、会员审核和权益转账状态。后台只保存密钥哈希，不会返回邮箱或密钥明文。

The same device key can submit a service request to the manual review queue and read that account's request history. Submission checks the catalog unit but does not reserve or deduct credits.

同一设备密钥可提交服务申请并查看本账户申请历史。提交时会核对目录积分，但不会预占或自动扣除 credits。

Access Boundaries 安全边界

  • This UI does not request custody, approvals, signatures, private keys, seed phrases, exchange API secrets, or withdrawal permission.
  • Wallet verification is a backend read-only eth_call against the official GCA contract on Base Mainnet.
  • 100 credits and GCA Member status are utility ledger records, not cash, income, reimbursement, trading permission, or risk-control bypass.
  • Account service requests require the device key, enter a manual review queue, and do not reserve or deduct credits at submission.
  • The 10,000 GCA member benefit remains pending manual reserve-wallet transfer review after eligibility is recorded.
  • 中文用户只需要提交公开资料：邮箱、Base 钱包地址、公开交易哈希和持有开始日期；不要提交任何敏感资料。
